## The Two-File System

```
pyproject.toml  →  (uv reads this)  →  uv.lock
   (What you want)                      (Exact versions locked)
```

### 1. pyproject.toml - Your Intent (Human-Editable)

**Purpose**: Declares what dependencies you WANT with flexible version ranges

**Example**:
```toml
dependencies = [
    "langchain>=1.1.0,<2.0.0",    # "I want LangChain 1.x"
    "fastapi>=0.123.0,<1.0.0",    # "I want FastAPI 0.123+"
    "pydantic>=2.12.5,<3.0.0",    # "I want Pydantic 2.x"
]
```

**Key Characteristics**:
- ✅ Human-readable and human-editable
- ✅ Defines version RANGES (e.g., `>=1.1.0,<2.0.0`)
- ✅ Lists only direct dependencies (what you explicitly need)
- ✅ Source of truth for what the project requires

### 2. uv.lock - Resolved Reality (Auto-Generated)

**Purpose**: Locks EXACT versions of ALL packages (including transitive dependencies)

**Example**:
```toml
[[package]]
name = "langchain"
version = "1.1.0"              # Exact version (not a range)
dependencies = [
    { name = "pydantic", version = "2.12.5" },      # Transitive dependency
    { name = "requests", version = "2.31.0" },      # Transitive dependency
    { name = "pydantic-core", version = "2.23.4" }, # Transitive of transitive
]
```

**Key Characteristics**:
- ✅ Auto-generated by `uv` (never edit manually)
- ✅ Contains EXACT versions (e.g., `1.1.0`, not `>=1.1.0`)
- ✅ Includes ALL dependencies (direct + transitive)
- ✅ Ensures reproducible builds across all environments

## How to Add Dependencies

### Step 1: Edit pyproject.toml

Open `pyproject.toml` and add your dependency to the `dependencies` array:

```toml
dependencies = [
    "langchain>=1.1.0,<2.0.0",
    "fastapi>=0.123.0,<1.0.0",
    "pandas>=2.0.0,<3.0.0",  # ← NEW: Add this line
]
```

**Version Range Guidelines**:
- Use `>=X.Y.Z,<X+1.0.0` for major version pinning (e.g., `>=1.1.0,<2.0.0`)
- Allows minor and patch updates within the same major version
- Prevents breaking changes from major version bumps

### Step 2: Run uv sync

```bash
uv sync
```

**What happens**:
1. `uv` reads `pyproject.toml`
2. Resolves all dependencies (including pandas and its transitive dependencies)
3. Updates `uv.lock` with exact versions
4. Installs packages to `.venv/`

### Step 3: Commit Both Files

```bash
git add pyproject.toml uv.lock
git commit -m "Add pandas dependency"
```

**Why commit both?**
- `pyproject.toml`: Shows WHAT you added
- `uv.lock`: Ensures teammates get the SAME exact versions

## How to Update Dependencies

### Update to Latest Within Ranges

Update all dependencies to the latest versions that satisfy the ranges in `pyproject.toml`:

```bash
uv lock --upgrade
uv sync
```

**Example**:
```toml
# pyproject.toml says:
"langchain>=1.1.0,<2.0.0"

# uv.lock currently has:
version = "1.1.0"

# After uv lock --upgrade:
version = "1.1.5"  (latest 1.x version)
```

### Update to New Major Version

**Step 1**: Edit `pyproject.toml` to change the version range:
```toml
# OLD
"langchain>=1.1.0,<2.0.0"

# NEW
"langchain>=2.0.0,<3.0.0"
```

**Step 2**: Sync to update lock:
```bash
uv sync
```

**Step 3**: Commit both files:
```bash
git add pyproject.toml uv.lock
git commit -m "Upgrade langchain to 2.x"
```

## How to Remove Dependencies

### Step 1: Remove from pyproject.toml

Delete the dependency line:
```toml
dependencies = [
    "langchain>=1.1.0,<2.0.0",
    "fastapi>=0.123.0,<1.0.0",
    # "pandas>=2.0.0,<3.0.0",  ← REMOVED
]
```

### Step 2: Run uv sync

```bash
uv sync
```

This removes the package from `.venv/` and updates `uv.lock`.

### Step 3: Commit Both Files

```bash
git add pyproject.toml uv.lock
git commit -m "Remove pandas dependency"
```

## Why We Have Both Files

### The Problem Without Lockfiles

**Scenario: Only pyproject.toml (no uv.lock)**

```
Day 1:  You install      → langchain>=1.1.0 → Gets 1.1.0
Day 30: Teammate clones  → langchain>=1.1.0 → Gets 1.1.5 (newer!)
Day 60: Production deploy→ langchain>=1.1.0 → Gets 1.2.0 (even newer!)

Result: "Works on my machine" syndrome 😞
Different versions = different bugs = unpredictable behavior
```

### The Solution With Lockfiles

**With pyproject.toml + uv.lock**

```
Day 1:  You install      → Locks langchain==1.1.0 in uv.lock
Day 30: Teammate clones  → Reads uv.lock → Gets 1.1.0 (same!)
Day 60: Production deploy→ Reads uv.lock → Gets 1.1.0 (same!)

Result: Reproducible builds ✅
Same versions everywhere = predictable behavior
```

### Real-World Analogy

Think of it like a recipe:

**pyproject.toml** = Recipe Instructions (Flexible)
```
"Add 1-2 cups of flour"    (flexible range)
"Add fresh tomatoes"       (latest available)
"Season to taste"          (developer choice)
```

**uv.lock** = Exact Ingredients Record (Reproducible)
```
"Used exactly 1.5 cups King Arthur All-Purpose Flour, batch #12345"
"Used 3 Roma tomatoes from Farmer's Market, picked Oct 15, 2024"
"Used 2 teaspoons Morton kosher salt"
```

**Why both?**
- Recipe (pyproject.toml) = Flexibility to adapt to what's available
- Exact record (uv.lock) = Others can reproduce your EXACT result

## Industry Best Practices

| File | Who Edits | Purpose | Commit to Git? |
|------|-----------|---------|----------------|
| **pyproject.toml** | ✅ You (manual) | Declare what you want | ✅ Yes |
| **uv.lock** | ❌ uv (auto) | Lock exact versions | ✅ Yes |

### Golden Rules

1. ✅ **ALWAYS edit pyproject.toml** to add/remove/update dependencies
2. ✅ **ALWAYS run `uv sync`** after editing pyproject.toml
3. ✅ **ALWAYS commit BOTH files** to git
4. ❌ **NEVER manually edit uv.lock**
5. ❌ **NEVER use `pip install`** (breaks the lock)
6. ✅ **Use version ranges** in pyproject.toml (e.g., `>=1.1.0,<2.0.0`)
7. ✅ **Review uv.lock changes** in pull requests

## Quick Reference

### Common Commands

```bash
# Add new dependency
# 1. Edit pyproject.toml (add dependency)
# 2. Run:
uv sync

# Update all dependencies to latest (within ranges)
uv lock --upgrade
uv sync

# Remove dependency
# 1. Edit pyproject.toml (remove dependency)
# 2. Run:
uv sync

# Fresh install (new teammate cloning repo)
uv sync  # Uses uv.lock for exact versions

# Show installed packages
uv pip list

# Show dependency tree
uv tree
```

### Version Range Syntax

| Pattern | Meaning | Example |
|---------|---------|---------|
| `>=1.1.0,<2.0.0` | Allow 1.x versions | LangChain 1.x |
| `>=1.1.0,<1.2.0` | Allow 1.1.x versions | Patch updates only |
| `==1.1.0` | Exact version (avoid) | Pin to specific version |
| `>=1.1.0` | Any version ≥ 1.1.0 (risky) | No upper bound |

**Recommended**: Use `>=X.Y.Z,<X+1.0.0` for most dependencies.

## Troubleshooting

### Issue: uv.lock is out of sync

**Symptom**: `uv sync` shows warnings about lock being out of sync

**Solution**:
```bash
# Regenerate lock file
uv lock
uv sync
```

### Issue: Dependency conflict

**Symptom**: `uv sync` reports conflicting version requirements

**Example**:
```
Package A requires langchain>=1.0.0,<2.0.0
Package B requires langchain>=2.0.0,<3.0.0
Cannot resolve!
```

**Solution**:
1. Check which packages have conflicting requirements
2. Update version ranges in `pyproject.toml` to be compatible
3. Or find alternative packages that are compatible

### Issue: Package not found

**Symptom**: `uv sync` reports package doesn't exist

**Solution**:
1. Verify package name is correct (check PyPI)
2. Check spelling and case sensitivity
3. Ensure package is published to PyPI

### Issue: Slow dependency resolution

**Symptom**: `uv sync` takes a long time

**Common Causes**:
- Complex dependency tree
- C extension compilation (e.g., grpcio)

**Solution**:
- Wait for completion (first install is slowest)
- Subsequent syncs are much faster (cached)

## Why uv Over Other Tools?

### vs pip (no lockfile)

| Feature | pip | uv |
|---------|-----|-----|
| Reproducible builds | ❌ No | ✅ Yes (uv.lock) |
| Speed | Slow | 10-100x faster |
| Dependency resolution | Basic | Advanced |

### vs pip + requirements.txt

| Feature | requirements.txt | uv |
|---------|------------------|-----|
| Version ranges | ❌ Manual management | ✅ Automatic |
| Lockfile | ❌ Manual | ✅ Auto-generated |
| Transitive deps | ❌ Manual tracking | ✅ Automatic |

### vs Poetry

| Feature | Poetry | uv |
|---------|--------|-----|
| Speed | Slow (Python) | 10-100x faster (Rust) |
| Lockfile | poetry.lock | uv.lock |
| Complexity | Higher | Lower |
| Tool ecosystem | Poetry-specific | Standard Python |

**Our Choice**: uv for speed, simplicity, and industry-standard `pyproject.toml` support.
